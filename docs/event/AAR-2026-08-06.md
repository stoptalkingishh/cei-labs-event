## 4. What went well

- **The engine concurrency work held.** The 2026-07-13/15 race fixes
  (atomic relaunch lifecycle, shared-SQLite port allocation, DB-native flag
  upsert) survived a live multi-team event with no repeat of the orphan-SSH /
  cold-500 class of failures. Deterministic 20-way gate was real acceptance
  evidence, not a paper claim.
- **Deterministic secrets work (2026-07-30).** Krypton 2/6 and Bandit 13→14
  reboots no longer regenerated flags/keys; per-team verifications held.
- **Score durability.** A clean CTFd MariaDB dump (256 KB, verified) was taken
  at event close and mirrored off-box; final scoreboard is recorded in SQL,
  not prose.
- **A genuinely live event.** Real teams, real solves (199 accepted from 399
  submissions), all four tracks active at close, platform at 1/1 across all
  five stack services through the event.
- **No data loss during rescue.** The CTFd DB password mismatch was repaired
  via a `mariadb:10.11 --skip-grant-tables` rescue container without purging
  the existing volume; the admin account was recovered with `hash_password`.

## 5. What went wrong (issues and root causes)

### Infrastructure / networking

1. **Stale Swarm advertise address after every subnet change.** The manager
   advertised dead `192.168.10.13:2377` after moving to `192.168.1.150`;
   workers joined successfully but couldn't reach the manager. Fixed by
   `leave --force` + re-init with `--advertise-addr` + worker rejoin —
   and this exact mistake was made twice across the July/Aug migrations.
2. **OPNsense server egress never worked.** DNS resolved locally and pings
   answered, but server outbound internet through the router stayed broken
   (WAN gateway `/NAT/rule` path). The Swarm was re-homed to `192.168.1.0/24`
   and the router was bypassed for the event. The OPNsense console-access
   issue (GUI/SSH blocked to agents) was a prerequisite gap.
3. **CTFd DB credential drift.** The persistent `cei-labs_ctfd_db_data`
   volume held passwords that no longer matched `docker/secrets/*.txt` →
   `Access denied for user 'ctfd'` after redeploy. Silent until restart.
4. **`.12` node never joined.** Docker installs stalled/slow on transport;
   the intended 4th node (`cei-ryzen5-15g-swarm04`) never participated.
   Event ran on 3 nodes.
5. **Sandbox false-failures.** TCP connectivity checks failed inside the
   sandbox but succeeded outside it (SSH 22, OPNsense 443, example.com 443),
   causing wasted debugging before rerunning outside the sandbox.
6. **Workstation LAN dropouts.** `192.168.10.120` intermittently dropped
   "media disconnected"/no route, blocking SSH mid-install and stalling
   Docker installs and CTFd resets repeatedly.

### Platform / content

7. **Per-team Krypton instance silently missing (Workhorse, team 22).**
   The orchestrator create failed on a Docker overlay-network race
   (`network chnet-22-group-krypton not found during service create`) and
   rolled back silently — team 22 had CTFd flag secrets but **no SSH box at
   all** while other teams had theirs. Same class of failure as the earlier
   "port 32009 can't login" report. Fixed via orchestrator API recreate
   (port 32018) + secret re-sync (ch 36–42). **Lesson: when a user reports
   "can't log in" to a per-team box, first check the orchestrator
   `instances` table — the instance may not exist.**
8. **Bandit per-team passwords rotated by a relaunch.** A relaunch
   regenerated per-team creds; old logins broke. Resume point was set to
   `bandit19 / bandit19`.
9. **User/game reset wiped the hint-wallet display cache.** The reset
   `DELETE`'d `hint_wallet_catalog_cache` → `409 no_active_catalog`, so no
   hints rendered for anyone. Rebuilt from the orchestrator's authoritative
   catalog (revision 9). **Lesson: a full CTFd user/progress reset must NOT
   clear that row.**
10. **Admin password double-hash bug.** CTFd's model auto-hashes `password`
    assignments, so the reset script double-hashed; the admin password had to
    be repaired via `CTFd.utils.crypto.hash_password` with round-trip verify.
11. **AI Copilot track hidden + not registered.** Deployed `hidden` at first
    and not registered with `wargame-stages` (it runs on participant
    laptops, so upstream excludes it); added as a 6/6 stage for this event.
12. **Generated-challenge clobber (pre-event).** Direct edit to a generated
    `challenge.yml` silently reverted on rerun; `challenges/` is a gitignored
    build artifact — source of truth is in `scripts/build_*.py`.

### Process / coordination

13. **Stale-clone / fetch-before-merge false negative (2026-07-15).** A
    "branch is unmerged" claim was made from a local clone that hadn't
    fetched `origin/main`; `git log --all` only sees fetched refs. Corrected
    in-place and codified as a standing rule.
14. **Cross-agent coordination was ad hoc.** No PRs at first, direct pushes to
    `main`/`master`, hand-updated tracker. The mcp-agentconnect router-queue
    existed but was never used. Later moved to PR-based merges.
15. **No live monitors during the event.** Peak CPU/mem/disk during play is
    unrecoverable — no `docker stats` loop or node-exporter ran. Only
    post-event idle state + node capacity could be recorded.
16. **Repeat failure: per-team instance silently not materialized.** Appeared
    at least twice across the event window (Krypton team 22; Bandit port 32009
    login), reinforcing the "verify the box exists before blaming creds"
    lesson.

## 6. Lessons learned (top recommendations)

1. **Subnet migrations are a checklist, not a task.** Advertise address,
   stack env vars (`ORCHESTRATOR_OFFLINE_HOST`), and DB secrets all migrate
   independently and silently. Write the migration checklist, then re-verify
   with `docker node ls` and `docker stack services cei-labs`.
2. **Reserve the rescue paths before event day.** Rehearse
   `mariadb --skip-grant-tables` credential realign and the CTFd
   `hash_password` admin recovery on a scratch stack, not during the event.
3. **Never clear `hint_wallet_catalog_cache` in a user/progress reset.**
   It is write-once-by-orchestrator; drop the table-wide DELETE from any
   future reset script.
4. **On "can't log in" reports, verify the instance exists first.** Check
   the orchestrator `instances` table and running services before touching
   credentials. Overlay-network create races can silently leave a team with
   secrets but no box.
5. **Monitor during the event.** A `docker stats` loop or
   Prometheus/node-exporter across the Swarm would have made real peak
   numbers recoverable. Treat "post-event idle only" as a known reporting
   gap next time.
6. **Preserve OPNsense console access.** Without console / root-GUI access,
   automated agents cannot repair upstream networking. Stow usable router
   access before event day.
7. **Backup before destructive changes, always.** The pre-reset CTFd dump is
   what made the admin-password recovery possible.
8. **Keep secrets deterministic.** The `/dev/urandom`-per-boot class of bugs
   (Krypton 2/6, Bandit 13→14) was fully preventable by deriving per-team
   secrets deterministically from stable `LEVEL_SECRETS`.
9. **`git fetch origin` before any merge-state claim.** `git log --all` /
   `git branch -r` only see fetched refs.
10. **Structure resets with the hint-wallet and scoreboard caches in mind**
    — a reset is a platform-operation, reviewed for its effect on every
    plugin table, not just users/solves.

## 9. Bottom line

The 2026-08-06 event **was delivered**: the engine's concurrency ground-work
held under live load, all four tracks ran, and scores were preserved. The
costs were almost entirely network/operational — OPNsense egress was
sacrificed, a node was dropped, and several silent infrastructure races
(resume-from-mistakes) had to be fought live. The most reusable output of this
AAR is the operational checklist: subnet-migration steps, rescue procedure
rehearsal, never-clearing `hint_wallet_catalog_cache`, verifying instances
before blaming credentials, and monitoring from minute one.
